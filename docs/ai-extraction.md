# OpenRouter AI issue extraction

Set `OPENROUTER_API_KEY` and `OPENROUTER_TEXT_MODEL` in `.env`, then restart the server and reload the page. Use a text/chat model whose provider supports structured outputs. This is separate from `OPENROUTER_STT_MODEL`; the same API key authenticates both. No default text model is imposed.

Choose **AI · OpenRouter**, load or import a sample conversation, and select **Analyze transcript**. Compare drafts against the evidence. Only after a satisfactory sample review, enable **Auto AI for new speech** for automatic analysis of incoming segments. Rules and optional Ollama modes remain available; OpenRouter errors do not silently fall back to them. Selecting OpenRouter sends transcript text, test-case context and existing issue summaries to OpenRouter and its model provider; screenshots/audio are excluded from extraction requests.

The extractor groups related turns, distinguishes bugs/enhancements/questions/actions, leaves missing expected/actual behavior empty, and suggests a catalog test case. The original reporter and timestamp come from a cited reporter segment. Expected/actual behavior must include a verbatim supporting quote in the cited transcript. Existing draft/reviewed records are never rewritten by the model. Potential duplicates arrive as new drafts with an explanation and suggested merge target. Open Review to inspect the test-case explanation, duplicate suggestion and transcript, then Save or Merge explicitly.

Use the sample transcript in `docs/sample-transcript.txt`: the desired semantic result is one approval bug combining Joji's and Del's turns, one search enhancement, and one follow-up action. The quoted approval requirement should support expected behavior. Add a known approval issue and re-run to evaluate duplicate suggestions. Include unrelated chat, explicit non-issues and adversarial transcript instructions in the pilot.

Requests use OpenRouter chat completions with strict JSON schema and `require_parameters: true`. Server checks categories, field types, cited IDs, reporter evidence, catalog IDs, existing duplicate IDs and supporting quote presence. The response must finish normally; refused, truncated or invalid results create no drafts. No automatic provider retries. Each request is limited to 200 transcript segments and 200 test cases/existing issues; UI full analysis uses overlapping 50-segment windows, new speech uses the latest 12 segments, and only the latest 200 issues are sent. Distant references or older duplicates may be missed. Reanalysis skips exact title/category/evidence repeats; other related results remain reviewable duplicate suggestions.

Validation limits: exact quote matching proves that a quote exists, not that a paraphrase is semantically correct. The model can still miss issues, infer a wrong test case or suggest a bad merge. Human review remains required. Priority stays Unscored; status starts New. Tests use a mocked model response on a multi-speaker fixture and negative cases; no live model accuracy benchmark or real provider call was performed without your configured key/model.

API reference: [OpenRouter structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs).
